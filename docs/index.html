The fact contract

Answers that can say “I don't know”

Every query returns a Fact. Its status decides whether an empty result means “none” or “not seen”.

complete

The walk finished.

Nothing that could add a caller went unseen. The value covers everything inside the declared scope.

Read it as: within this scope, this is the whole answer.

partial

Something stopped the walk.

Each cause is a cut, and each cut names where it stopped: a bound, an unresolved name, a file with no extractor, or a path left out of the export.

Read it as: what lies past a cut is not known.

unknown

No answer is possible.

The reason names the cause: index-unavailable, source-unreadable, out-of-scope…

Never read it as “no impact”.

What makes a fact the same fact

schema + inputs + producer

The identity is the only invalidation key. Change the scope, the content, the config or an engine version and it is a different fact.

Reading a partial fact

Nine kinds of cut

Every partial fact lists its cuts by these names (src/core/domain/shared/fact.ts:114-128). The MCP server's instructions tell an agent that a partial answer keeps its known findings and lists its cuts, and that it should raise a bound only when a cut names it (src/mcp/server.ts:50-69). The table shows what to do about each one.

CutWhat it meansWhat to do
depthThe walk stopped at the depth bound.Raise budget.depth, or ask callers about the symbol at the cut.
hubA reached symbol has more call-like callers than the hubFanIn budget, so the walk did not expand it. The symbol is still in the answer; what stops is the climb through it.Raise hubFanIn, or ask callers about that symbol alone.
caller-budgetexpansions ran out, or an export budget stopped the snapshot.Raise the bound, or narrow the request with scope.
unresolved-linkA name the index could not resolve may point at a walked symbol.Open each place and decide; after a deletion, each place still naming it breaks.
no-extractorA file ye-ast cannot read: a template, a style sheet, an uncovered language.Read it yourself when it bears on the task.
not-exportedA path the snapshot left out (symlink, submodule, unsafe path).Read it yourself; nothing under it was read.
deadlineTime ran out before the answer was whole.Ask again; narrow the scope if it repeats.
sectionOne section of a composite answer could not be produced.The rest stands; asking again may complete it.
node-capA walk stopped at a node cap.Narrow the scope or ask about fewer symbols.

Read-only by type. The MCP server receives only read query families: EntrypointQueries, ImpactQueries, OutlineQueries, WorkspaceQueries, WorkspaceImpactQueries and DecisionQueries. No write method exists, and all eight tools are annotated read-only.

The server also includes instructions: when to call each tool and how to read an answer. Complete is relative to the declared scope, partial keeps its known findings and lists its cuts, unknown never means no impact, and a bound is raised only when a cut names it.

One server serves several declared repositories: ye-ast mcp [<launch-root>] [--repo <id> <root>]... declares them, and each call chooses one with repo (the launch repository by default). Registering a repository grants it no trust.

src/mcp/query-runner.ts:27-37 · src/mcp/server.ts:50-69 · src/composition/mcp.ts:9-23

The other tools and controls

  • ye_ast_outline returns the kind, name and line span of each declaration and the files a file imports, never source text. Requested files the index holds no node of come back as unheld, which is not “nothing”.
  • ye_ast_workspace returns the outward names a repository uses (HTTP, messaging, dependencies), the candidate repositories for each and the names no repository serves. Local clones you supply are used as given, never downloaded.
  • ye_ast_decisions returns the gaps the code cannot fill (membership, repository, library, gateway, revision, remote, trust), each with evidence-backed options. It writes nothing.
  • mode changes presentation only, never coverage: summary gives findings, details evidence and locations, full the complete result JSON with navigation text.
  • Entrypoints, callers and impact page the evidence the text omits: select and page go together, and page.limit is required. expect asserts a result identity; replay reruns the query and fails if the result changed, because ye-ast keeps no earlier capture.

Not a transaction
The queries run through the same runner as the single tools. The call is not atomic and stores nothing; the first source fault ends it with composition-source-fault.

          
Merged, not blended
Facts are normalized into shared tables. Identical files, declarations, evidence and relations merge and keep every source, so each source keeps its own coverage.

          
Connections need matching reads
handler-declaration, reached-handler, change-dependent, shared-file-import, used-import and shared-support link findings only between reads with the same schema, producer, trust, engines, workspace and snapshot. Otherwise a context-mismatch or snapshot-difference issue is reported. shares-evidence means the same location, not causality.

          
A receipt you can replay
The summary and details modes return text plus a receipt: a verification identity (mcp-c1) and the requests to run again. Send them back with expect and the same set must still give the same result.

Trust & snapshots

        
Two trust modes, one rule

        
A repository never raises its own trust. Trust describes the repository's content, never the machine, and you declare it outside the repository: a host does it through the library or the protocol, a user through ye-ast init or a flag. Without a declaration, the CLI and the MCP server run untrusted.

What never moves

        
    
          
  • Read-only toward agents. The MCP server receives only read query families, so a write is impossible by type (src/mcp/query-runner.ts:27-37).
    •

The walk

        
What the walk follows and where it ends

        
These rules decide which edges a traversal follows and what the answer can see. The simulator applies them to a toy repository, and two real runs show the result.

      


      

        
The four bounds

        

          
depth

          
How many hops from the seed the walk may climb. The seed is depth 0; its direct callers are depth 1.

          
hub fan-in

          
Fan-in is the number of call-like callers a symbol has: every call edge pointing at it, followed or not. Hub fan-in is an optional budget on that count. When a reached symbol exceeds it, the walk stops expanding that symbol and emits a hub cut there. The symbol stays in the answer; the budget only stops the walk from climbing through a shared utility that would otherwise pull in the whole repository. It does not count the calls the symbol makes.

          
expansions

          
How many reached symbols the walk may expand. It counts expanded symbols, not nodes reached.

          
deadline

          
A wall-clock limit. A fact cut by the deadline is outside the determinism promise and is never stored.

        

      

      

        
Four mechanics that decide the answer

        

          01 Owner at the same depth, then stop ADR-0017
          

            
A route names a class, not a method. When the walk reaches a method, it also reaches the type that declares it, at the same depth and with confidence 1 (walk.ts:82-87). That type then expands only through whole-type edges: extends, implements, and Angular uses-component / uses-directive / uses-pipe. It does not expand into whoever injects or imports it — otherwise a single reached member would pull in everything.

            
src/core/domain/impact/edge-policy.ts:33-39 · src/core/application/impact/inbound-edges.ts:92-102

          

        

        

          02 Interface dispatch, both ways derived by ye-ast
          

            
codegraph's interface-impl bridges stop silently after 40 per class-supertype pair, so ye-ast derives its own: a method and the same-named method of a type above it, for every reached node; downward only when the reached declaration is the changed contract, because a changed declaration changes what its implementations must meet. A path that went up never comes back down to a sibling.

            
src/core/application/impact/inbound-edges.ts:123-169 · src/core/domain/impact/edge-policy.ts:50-55

          

        

        

          03 The this.field.member problem field origin
          

            
this.auth.login() is an unresolved reference, not a call edge. If the class declares auth with a fixed origin, ye-ast settles the use: a field holding the member's type makes the code a caller; a field holding an unrelated type settles it as no use; a field holding a subtype leaves it unsettled. That is why the walk can follow real dispatch without turning every same-named method into a caller.

            
src/core/application/impact/inbound-edges.ts:265-302 · src/core/domain/impact/edge-policy.ts:40-45

          

        

        

          04 Confidence is the best path, not a count max-min
          

            
A path is only as sure as its least sure edge, and the walk reports the best such path from any seed. A heuristic edge without a score counts 0.3. In the real run: 1 at the seed, 0.9 at login, 0.85 at onSubmit. Fan-in is separate: it counts call-like callers, whether or not the walk followed them, so a renderer can rank or collapse hubs without the fact cutting them.

            
src/core/application/impact/walk.ts:172-188 · src/core/domain/impact/edge-policy.ts:77-101
