## Usability for an agent

- The summary never shows the call tree: only roots, effects, the reading plan and grouped cuts. To learn what a route
  runs, an agent must ask for details, which is 2 to 8 times larger. The reading plan and the effects are the most useful
  parts.
- Cut noise dominates. For example, PCM-1 has 15 cuts and 2 are informative. Cuts carry no reason ("aspect veto",
  "library call", "generated code", "ambiguous"), and library cuts sit beside real flow boundaries with equal weight.
- External spelling repeats every prefix of a fluent chain, with its newlines.
- At baseline, `ye_ast_compose` carrying a single trace dropped the direct summary effects line; the multi-repository implementation restores an effects count.
- Latency on the largest Java backend was 18 to 55 s per call on a loaded host. `--measure` has no stage for the trace
  walk, where most of the time goes.

## Multi-repository analysis

### Baseline: trace reads one repository; workspace reads the declared libraries

- `workspace`, `impact` and `callers` read every repository of a declared workspace. Through the dependency closure, they
  pass each repository's declared library sources into call-site and entrypoint extraction:
  `src/core/application/topology/workspace-queries.ts` (`withDependencies`, `deps.callSites.of(entry.sources, repo,
  librarySources)`), with provenance from `src/core/domain/topology/library-source.ts`.
- Trace has no workspace and no library-source input (`src/core/ports/trace-queries.port.ts`). It extracts placed call
  sites from the root snapshot's sources only (`src/core/application/trace/trace-queries.ts`).
- So a call through a project-owned client library is invisible inside trace, even when `workspace` reads that library.

### Measured on the acceptance repositories (slice 4)

- **The acceptance service** publishes and calls through the organization's own NATS and REST client libraries. Their
  source is not in the snapshot, so its 6 call sites are cuts `<kind> effect through <library>`. There are 0 resolved
  effects.
- **The acceptance frontend's wrapper** builds its URL through a helper of another injected service. That helper
  substitutes placeholders, checks for absolute URLs, chooses a base from options or configuration, trims slashes and
  concatenates. The RFC-0011 wrapper rule follows only same-class helpers that forward a parameter as an unchanged path
  tail (`src/core/adapters/typescript/http-call-sites.adapter.ts`), so it cannot follow this helper. Treating the helper
  as forwarding would assert something the code does not prove, and part of the URL is only known at run time. There are
  0 resolved effects.

### Baseline: compose does not join a trace effect with a workspace link

- Compose is transversal by design. Each executed source is normalized into evidence by typed fields; identical objects
  share one record; relations come from shared identity, never from code written for a pair of families. One link read
  by two families becomes one `workspace-match` relation (`src/mcp/composition-normalize.ts`, `linkData`).
- Trace effects are not normalized as call-site evidence. They stay nested in the `trace-step` part
  (`composition-normalize.ts`, the trace step adapter). So a trace effect and the workspace link that starts at the same
  call place share no identity, and no relation forms. A `trace + workspace` composition shows them side by side, and
  the agent has to match them itself.
- The transversal fix, a **hypothesis** not yet built: give a trace effect the same call-place identity (repository,
  file, line) that `Link.from` and the `call-site` part already use. Every composition that holds both a trace and a
  workspace-capable read then relates them, with no pair-specific code.

## Suggested order of work

1. **False facts:**
   - D1: an effect must come from a traversed body; deduplicate identical effects.
   - D2: overload by argument count.
   - D3: resolve an inherited member through the declared super-interface before name lookup.
   - D4: signal store state is not an interface field.
   - D5: report the effect when the root is the client method.
2. **D9:** scope the aspect veto to the types its pointcut can match, or treat advice as wrapping. Allow stereotype
   annotations on interfaces. Keep the veto where a proxy may replace the body. State the reason on the cut.
3. **D6-D8:**
   - Never offer candidates from another language, a configuration file or another deployable module.
   - Classify imported library symbols as external.
4. **Summary shape:**
   - A two-level step outline with `file:line`.
   - Cuts split into flow boundaries and library or generated code, each with a reason.
5. **D10, D11, D12** and a `trace-walk` stage in `--measure`.
6. **Multi-repository:**
   - The approved workspace-sources option above is implemented; runtime URL helper semantics remain outside scope.
   - Transversal call-place identity for trace effects in compose is implemented.

Fixes must follow the general fail-closed rule: a form that cannot be proven becomes a cut, and no fix patches one
variant at a time. The bounded review policy applies: a finding blocks only when it breaks an invariant.
