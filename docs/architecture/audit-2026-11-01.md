## Progress against the MVP

The MVP serves one stack: Java and Spring for the backend, TypeScript and Angular for the frontend, as the owner declares
and as `MAP_SCOPE` states ([`entrypoint-map.ts:23`](../../src/core/domain/map/entrypoint-map.ts)).

Order from [ADR-0011](adr/0011-query-protocol-in-the-mvp.md) decision 5, which supersedes ADR-0005 decisions 2–3.

| MVP deliverable | State |
|---|---|
| The library | **Partial.** The core is genuinely embeddable (use cases take ports, `composeCli` is the only wiring), but there is no package entry point, no `exports` map and no `FixedLayerAdmin`/`SnapshotAdmin`, so a host cannot consume it as the documents describe. |
| `ye-ast map` | **Slice 1 only.** `EntrypointMap` is `{ entrypoints }` ([`entrypoint-map.ts:17`](../../src/core/domain/map/entrypoint-map.ts)), so the implementation files per entrypoint exist only as the handler ([`http-route.ts:26-30`](../../src/core/domain/entrypoints/http-route.ts)) without the declared resources or the graph closure, and slices 2 (operations and links) and 3 (live tree) are absent ([RFC-0004](rfc/0004-deterministic-map.md) "Slices"). |
| `ye-ast install` | **Absent.** Not in `USAGE` or `queryOf` ([`main.ts:33-95`](../../src/cli/main.ts)). |
| `ye-ast serve` (query protocol, stdio) | **In progress.** Absent at `30a5832`; `src/composition/serve.ts` and `src/protocol/` are in the working tree at `ec4ac0d`, not yet in `USAGE`. `SnapshotAdmin` is still missing. |
| stdio MCP server | **Shipped** at `ec4ac0d` (`ec4ac0d`, "serve entrypoints and impact as read-only MCP tools with ye-ast mcp"): `ye-ast mcp [<repo>]` answers `initialize` and lists four tools, and AGENTS.md documents it. Absent at the audited base. |
| Hooks, daemon | Correctly deferred; nothing started. |

Outside the MVP but shipped ahead of it: `impact` ([RFC-0010](rfc/0010-impact-queries.md)), `callers`, `importers`,
the Angular relation reader, and per-user index reuse ([ADR-0015](adr/0015-index-reuse-by-content.md)) — the impact
family is built before the delivery order that ADR-0011 sets. That is a deliberate deviation, not a defect, but it means
the first consumer (qayaba) had no channel to reach any of it at the audited base: qayaba embeds the library or speaks the
protocol, and neither existed yet. The parallel session is closing that gap now.

## What conforms, with evidence

- **The envelope is the contract.** [`fact.ts:21-96`](../../src/core/domain/shared/fact.ts) reproduces RFC-0002's
  `Fact<T>` field for field, with the two closed sets identical (`UnknownReason` 6 members, `Cut.kind` 9 members) and a
  stricter `cuts: readonly [Cut, ...Cut[]]` that makes an empty `partial` unrepresentable. `composeSections` emits one
  `section` cut per incomplete section, sorted ([`fact.ts:101-108`](../../src/core/domain/shared/fact.ts)).
- **Determinism holds in practice**, not only by design: both `map` and `impact` produced identical bytes on repeated
  runs, every path is repo-relative, engines are sorted by name ([`impact-queries.ts:54`](../../src/core/application/impact/impact-queries.ts)),
  and the edge-policy digest is part of the producer version ([`compose.ts:67`](../../src/composition/compose.ts)) so a
  policy change invalidates stored facts.
- **The diff is machine-independent.** `merge-base` and the diff run isolated (`GIT_CONFIG_GLOBAL=/dev/null`,
  `GIT_CONFIG_NOSYSTEM=1`, `GIT_ALLOW_PROTOCOL` refusing every transport) and the hunk-deciding options are all passed
  explicitly ([`git-vcs.adapter.ts:205-219,339-346`](../../src/core/adapters/git/git-vcs.adapter.ts)). Exactly what
  RFC-0010 "The change" requires.
- **The export never trusts the repository.** Symlinks, submodules and unsafe paths are reported, not written
  ([`git-vcs.adapter.ts:70,256`](../../src/core/adapters/git/git-vcs.adapter.ts)); blobs are streamed through
  `cat-file --batch` with entry and byte budgets that stop at the first path not taken, which is the `caller-budget` cut
  of RFC-0006.
- **The index cache implements ADR-0015 faithfully**: content digest plus codegraph release, store schema and staging
  rules as the key ([`cached-index.adapter.ts:32-33`](../../src/core/adapters/codegraph/cached-index.adapter.ts)), build
  in a temporary directory and publish by atomic rename, and a cache that is a symlink or owned by another account is
  refused rather than repaired ([`:103-110`](../../src/core/adapters/codegraph/cached-index.adapter.ts)).
- **Exit codes and typed faults** match RFC-0005 to the number ([`main.ts:14,61-70`](../../src/cli/main.ts)), and a
  budget cut still answers with exit 0, as RFC-0010 requires.
- **The layering gate is real.** `depcruise` cruises 145 modules and 562 dependencies with zero violations, including
  `options.tsPreCompilationDeps: true`, which is what closes the type-only leak the 2026-10-29 review found. The one
  frozen exception (`spring` reading `tree-sitter`) is declared in the config, not hidden.
- **Redaction is at egress, keys included** ([`pattern-redaction.adapter.ts:163-168`](../../src/core/adapters/redaction/pattern-redaction.adapter.ts)),
  as RFC-0002 rule 7 demands.

## Defects

Ordered by severity. Each is candidate-caused: the base state at the cited commit, not a pre-existing condition.

### D1 — the map answers `complete` with nothing for a file it cannot read, and never emits `out-of-scope` (Medium — **fixed in `b32b0fe`**)

**Claim.** Two cases inside the MVP's own stack. An Angular project whose routes are plain JavaScript is mapped as
`status: complete` with zero entrypoints and zero cuts. And any file outside the declared languages produces no statement
at all: neither the `out-of-scope` reason RFC-0002 rule 4 prescribes for it, nor the `no-extractor` cut the impact path
emits for the same file.

**Evidence.** Repositories built for the test and mapped at `HEAD`:

```
js-angular  status=complete  routes=0  cuts=[]        # package.json names @angular/core and @angular/router
py          status=complete  routes=0  cuts=[]
go          status=complete  routes=0  cuts=[]
kt          status=partial   routes=0  cuts=["no-extractor:C.kt"]
```

`isInMapScope` admits only `isTypeScriptSource` for the frontend
([`entrypoint-map.ts:42-44`](../../src/core/domain/map/entrypoint-map.ts)), which excludes `.js`, `.mjs` and `.cjs`;
`exportCuts` cuts only for `isUnsupportedJvmSource`, whose set is `\.(kt|kts|groovy|scala)$`
([`:25,108-120`](../../src/core/domain/map/entrypoint-map.ts)). The generic classifier already exists and already calls a
`.js` file *"code in a language ye-ast declares no extractor for"*: `UNCOVERED_LANGUAGE` in
[`changed-file.ts:11-16`](../../src/core/domain/change/changed-file.ts). The impact path uses it and answers `partial`
with `no-extractor:app.py` for the same repository, verified; the map path never does.

**What the MVP scope does and does not excuse.** The owner declares the MVP as Java and Spring for the backend and
TypeScript and Angular for the frontend, and `MAP_SCOPE` matches that exactly
([`entrypoint-map.ts:23`](../../src/core/domain/map/entrypoint-map.ts)). RFC-0002 rule 4 makes `complete` relative to
`declaredScope`, so a Python service answering nothing is legitimately outside the promise — **that part is not a
defect**, and the first reading of this finding overstated it. What survives is narrower and still real:

1. **Angular does not require TypeScript.** A `package.json` naming `@angular/router` beside `.js` sources is a supported
   project shape, and the map then answers "verified none within the scope" about routes that exist. This sits in the
   MVP's own frontend half.
2. **`out-of-scope` has no producer.** Rule 4 says anything outside the scope "answers `out-of-scope`"; `grep
   out-of-scope src/` finds the union member and nothing that emits it, so the reader gets silence where the contract
   prescribes a reason.
3. **One product, two answers.** The same file is `uncovered` to `impact` and invisible to `map`. Whatever the answer
   should be, it should be the same one.

**Contract impact.** RFC-0002 rule 1 ([`rfc/0002:81-83`](rfc/0002-facts-contract.md)), the cut rule for a language with
no extractor ([`:88-90`](rfc/0002-facts-contract.md)), and rule 4 ([`:96-101`](rfc/0002-facts-contract.md)), which is the
rule the MVP scope reading rests on. ADR-0013 "fail loud" and the AGENTS.md invariant "an empty result never stands for
'no impact'" say the same.

**Smallest fix.** Admit the uncovered source extensions to `isInMapScope` so the export carries them, and cut every
exported file that `kindOfChangedFile` classifies as `uncovered`, reusing that classifier instead of a second language
list. A test whose repository holds a `.js` route table under an Angular `package.json` and asserts `partial` closes the
rule; if Angular-in-JavaScript is out of scope for slice 1, the cut is still the honest answer and the same test passes.

**Related, and not the same defect.** RFC-0004 slice 1 also lists the contract-sourced HTTP routes, and no OpenAPI
document reader exists (`yaml` serves only the Spring config). The code does not hide it: a generated `*Api` interface
reports `unknown` items at every delegate method
([`api-delegates.ts:30-41`](../../src/core/adapters/spring/api-delegates.ts)). That is a coverage gap declared out loud —
which is why it ranks below D1, and why it matters for a consumer such as qayaba whose routes live only in the generated
interface.

### D2 — `inputs.content` is not a function of the snapshot (Medium)

**Claim.** For one snapshot, two runs of the same query can publish different `inputs.content` digests, because the
failure paths digest a different thing than the success path.

**Evidence.** The success paths digest the export fingerprint
([`impact-queries.ts:132,177`](../../src/core/application/impact/impact-queries.ts)); the `unknown("index-unavailable")`
and `unknown("source-unreadable")` paths digest `JSON.stringify([mergeBase, head])` instead
([`:114-116,189,225`](../../src/core/application/impact/impact-queries.ts)). The first time a repository is queried its
index may be unavailable and the second time present, so the identical snapshot yields two `content` digests.

**Contract impact.** RFC-0002 rule 5 makes `inputs` the only invalidation key. A digest that changes with process state
rather than with content defeats caching and makes two facts for the same snapshot incomparable.

**Smallest fix.** Compute the content fingerprint before the first branch that can answer `unknown`, and pass it in; the
`unknown` path already has the export it needs at `:124-127` for the head and, when the extraction failed, can fall back
to the commit pair only with the `source-unreadable` reason.

### D3 — `Cut.at` has an undocumented, polymorphic grammar, and `no-extractor` carries two meanings (Medium)

**Claim.** `Cut.at` is `string[]`, but the meaning of an element depends on the cut kind and on its position, and one
kind is reused for a construct it does not name.

**Evidence.** Four incompatible encodings coexist:

| Emitted at | `at` |
|---|---|
| [`walk.ts:107`](../../src/core/application/impact/walk.ts) | `["<file>::<symbol>", ...]` |
| [`impact-cuts.ts:54,72`](../../src/core/domain/impact/impact-cuts.ts) | `["<file>::<declaration>", "<file>:<line>", ...]` — lead first, places after |
| [`impact-cuts.ts:91`](../../src/core/domain/impact/impact-cuts.ts) | `["<path>", "<path>:<line> <reason>", ...]`, emitted as `no-extractor` for an Angular relation the reader could not place |
| [`entrypoint-map.ts:110-123`](../../src/core/domain/map/entrypoint-map.ts) | `["<path>"]` |

RFC-0002 defines `at` as "where the computation stopped: repo-relative paths or symbols"
([`rfc/0002:58-65`](rfc/0002-facts-contract.md)), which permits all four; it does not tell a consumer how to read
them. Worse, `no-extractor` is defined as a file whose language has no extractor, yet at
[`impact-cuts.ts:91`](../../src/core/domain/impact/impact-cuts.ts) it means "this template's relation was unreadable" —
which RFC-0002 rule 2 assigns to an `unknown` item, not to a cut.

**Consequence.** Any consumer that filters `no-extractor` by `at[0]` to answer "which files are unmapped" reports the
wrong files, and cannot tell a symbol from a call site without parsing strings. A host that draws a cut in an editor
needs the positions, not a formatted label payload.

**Smallest fix.** Two decisions, both documentation-first: write the `at` grammar per kind into RFC-0002 (it is already
the de facto contract), and give the unread-relation cut a kind of its own, or move it to an `unknown` item.

### D4 — `engines` claims an engine that took no part (Low)

`map` reports `@angular/compiler`, `tree-sitter-java`, `typescript` and `web-tree-sitter` on a repository with no
Angular template anywhere, because the list is fixed for both use cases
([`compose.ts:23,51,68`](../../src/composition/compose.ts)) while the map path never reads a template
(`angular-routes.adapter.ts` imports only `typescript` and `route-table.loader.ts`). RFC-0002 says `engines` "holds only
those engines [that produced the fact]" ([`rfc/0002:69-71`](rfc/0002-facts-contract.md)). Over-reporting is safe for
invalidation and wrong for provenance: it makes two facts for the same snapshot differ after an unrelated package
upgrade.

### D5 — `parseTarget` splits on the last colon (Low)

[`main.ts:193-200`](../../src/cli/main.ts) treats everything after the last `:` as the symbol, so `src/a.ts:ns::fn`
reads as file `src/a.ts:ns`. Harmless today (Java and TypeScript symbols hold no colon) and a trap the moment a language
with `::` qualified names gains an extractor — and ADR-0013 keeps opening that door.

### D6 — redacting object keys can merge two entries (Low)

[`pattern-redaction.adapter.ts:163-168`](../../src/core/adapters/redaction/pattern-redaction.adapter.ts) rebuilds
objects with `Object.fromEntries` after redacting keys — it moved behind the port in `41e620b` with the behaviour
unchanged. Two keys that redact to the same text collapse into one, silently dropping a value. Determinism in, silent loss
out. Only reachable when a redaction pattern matches a symbol or path name, so probability is low; so is the cost of the
guard.

### D7 — `DeclaredScope` has no `include`/`exclude` (Low)

RFC-0002 says `scope` digests "the declared scope (languages, frameworks, include and exclude)"
([`rfc/0002:66-68`](rfc/0002-facts-contract.md)) and RFC-0006 makes the scope profile fields a host sets
([`rfc/0006:42`](rfc/0006-configuration.md)). The type has two of the four
([`fact.ts:16-19`](../../src/core/domain/shared/fact.ts)) and the value is the hard-coded
`MAP_SCOPE` ([`entrypoint-map.ts:23`](../../src/core/domain/map/entrypoint-map.ts)). Every fact today declares a scope
the caller could not choose. Adding the fields later changes `scope` digests, so this is cheaper to settle before the
first store exists.

### D8 — cut ordering is undefined for three of the nine kinds (Low)

`CUT_ORDER` lists six kinds ([`impact-fact.ts:59`](../../src/core/domain/impact/impact-fact.ts)); `deadline`, `node-cap`
and `section` get `indexOf === -1` and sort first. No producer emits them yet except `section`, so nothing is lost today
— but the day a deadline cut lands it will be ordered by accident, and RFC-0002 requires it to be identifiable as
outside the determinism promise.

## Test quality

The discipline the project asks for is visible in the titles, not only in the count: "a false positive only adds unknown
items, a missed one would hide routes", "a class named like a test is a test file outside the main source set, never
inside it", "a template the export left out is a `not-exported` cut". Each names a rule a realistic regression could
break, which is the standard `.claude/skills/ye-ast-testing` sets.

Strengths: 9 795 test lines against 8 191 production lines; fakes implement ports, process boundaries are doubled
(`GitDeps`, `CodeGraphDeps`) and nothing else; temporary state goes to `tmpdir()` with `mkdtemp` and is removed in
`afterEach`; one e2e runs real `git` with an isolated config and the real codegraph indexer, with no network.

Gaps, in the order they cost:

1. **No conformance fixtures as data.** ADR-0013 requires a fixture per plugin "seen failing first", plus two real
   applications and one parity diff per family. `find src -type f ! -name '*.ts'` returns nothing: every fixture is an
   inline string. A corpus on disk is what keeps a regression visible across refactors of the extractor.
2. **The rule D1 breaks has no test.** Kotlin is covered; nothing asserts that a `.py` file cuts the map, which is why
   the omission survived 757 green tests.
3. **Contract surface with no producer or no test**: `out-of-scope` (never emitted), `deadline` and `node-cap` (never
   emitted, no ordering), and `CodeGraphReader.fanIn`/`routes`, called only from the adapter's own test — dead port
   surface under the "reuse before creating" rule.
4. **Indirection in attribution, not in coverage**: `angular-router.extractor.ts` (443 lines) and
   `route-table.loader.ts` (354 lines) have no direct test; both are exercised through the 710-line
   `angular-routes.adapter.test.ts`. Correct by the seam rule, coarse when one of them breaks.

## Architectural sustainability

What will absorb `serve`, the MCP and the trust modes without rework: the port set (12 driven, 2 driving), the fact
envelope, the deterministic producer version, `SnapshotRef` already modelling `sha` and `live`, and `composeCli` as the
single wiring point. The CLI is already the thin adapter the documents describe: it knows only ports and domain types
([`main.ts:3-7`](../../src/cli/main.ts)), so a `serve` or MCP front end can reuse the same use cases unchanged.

What strains, in order of cost:

1. **`trust` is a literal.** `trust: "untrusted"` is hard-coded in both use cases
   ([`entrypoint-queries.ts:57`](../../src/core/application/entrypoints/entrypoint-queries.ts),
   [`impact-queries.ts:63`](../../src/core/application/impact/impact-queries.ts)). ADR-0010 makes the mode a declaration
   from outside the repository; today no path can raise it, so the `trusted` branch — live reads, manifest, `.gitignore`,
   remote refresh — has no seam to land in and D1's fix must not accidentally depend on the mode.
2. **Three ports named by the documents do not exist**: `FixedLayerStore`, `FixedLayerAdmin`, `SnapshotAdmin`, plus the
   documents and telemetry ports. `map`'s output is described as "directly the agnostic fixed layer"
   ([`rfc/0004:24`](rfc/0004-deterministic-map.md)) and nothing writes it. This is the largest single piece of MVP
   work left, and it is what `install` and the MCP are blocked on.
3. **A driven port is satisfied by an application module.** `RelationExtractor` is declared in `core/ports` and
   implemented in `core/application` ([`angular-relations.ts:21-23`](../../src/core/application/relations/angular-relations.ts)),
   which RFC-0001's table reads as "adapters implement [ports]". It is legitimate orchestration (it composes two driven
   ports and belongs in `application`) but the port makes it look like an adapter, and `composition` wires an
   application object as another use case's dependency. Either the port moves to `application` as a collaborator
   interface, or RFC-0001 states that a port may be satisfied by application logic.
4. **The scope is a constant, not an input.** D7 in code terms: when the first host wants `include`/`exclude` or a
   second language, `MAP_SCOPE` has to become a parameter threaded through both use cases and the digest. Cheap now,
   a schema change later.
5. **`map`'s value shape is a one-section composite.** Slices 2 and 3 add sections; `SCHEMA` is `0.1.0` and no store
   exists yet, so the major-version bump RFC-0002 rule 6 requires is free — but only until `install` writes the first
   fixed layer.

## Documentation hygiene

The 2026-10-29 review (`odd/tasks/architecture-review-fixes.md`) already reconciled 19 errors, 15 contradictions and 19
design gaps, and the records are consistent with the code on the points it touched. Two markers stayed stale after it:

- ADR-0010 still lists "who exports the snapshot, owns the store and supplies the scope" and "where the user-level
  trust record lives" as not decided ([`adr/0010:93-100`](adr/0010-trust-modes.md)), while RFC-0006 answers both and
  dates the decision 2026-11-01 ([`rfc/0006:99-100`](rfc/0006-configuration.md)).
- RFC-0006 question 4's answer (per-user cache, `$XDG_CACHE_HOME/ye-ast/`) is the behaviour `compose.ts` implements;
  ADR-0010's "Not decided here" should point at it instead of calling it open.

## Recommended order

1. **D1**, with its test. Reusing the classifier `impact` already applies is a small change, and it closes the one place
   where a `complete` fact inside the MVP's own stack hides something. Do it before `install`, because the first fixed
   layer will store these facts.
2. **D7 + `MAP_SCOPE` as a parameter.** Both change `scope`/`declaredScope` digests; free now, a schema major later.
3. **D2**, before any consumer starts caching on `inputs`.
4. **D3**, as a documentation change in RFC-0002 plus the one cut-kind rename in code.
5. `SnapshotAdmin`, `FixedLayerStore`, `FixedLayerAdmin`, then `ye-ast install` — the MVP's largest remaining block.
6. `serve` over the existing use cases, then the MCP on top of it.
7. **D4-D8** as they are touched by the work above.
