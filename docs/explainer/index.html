03 · The fact contract

An answer that can say “I don't know”.

Every query returns a Fact. The status is not a footnote: it decides whether an empty result means “none” or “not seen”.

complete

The frontier emptied.

Nothing that could add a caller was unseen. The value is everything inside the declared scope.

Read it as: within this scope, this is the whole answer.

partial

Something stopped the work.

Every cause is a cut, and each cut names where it stopped: a bound, an unresolved name, a file with no extractor, a path left out of the export.

Read it as: what lies past a cut is not known.

unknown

No answer is possible.

The reason says why: index-unavailable, source-unreadable, out-of-scope…

Never read it as “no impact”.

What makes a fact the same fact

schema + inputs + producer

The identity is the only invalidation key. Change the scope, the content, the config or an engine version and it is a different fact.

src/core/domain/shared/fact.ts:172-178 · RFC-0002 rule 5

trust trusted | untrusted scope languages, frameworks, include, exclude content digest of the exported bytes config bounds, targets, files origin full | sync engines exact versions

The cut taxonomy

Nine ways to be honest.

These are the same names the MCP server hands to an agent, with the action to take at each one (src/mcp/server.ts:39-50).

CutWhat it meansWhat a consumer should do
depthThe walk stopped at the depth bound.Raise budget.depth, or ask callers about the symbol at the cut.
hubA symbol has more callers than hubFanIn; it was not expanded.Raise the bound, or ask about that symbol alone.
caller-budgetexpansions ran out, or an export budget stopped the snapshot.Raise the bound, or narrow the request with scope.
unresolved-linkA name the index could not resolve may point at a walked symbol.Open each place and decide; after a deletion, each place still naming it breaks.
no-extractorA file ye-ast cannot read: a template, a style sheet, an uncovered language.Read it yourself when it bears on the task.
not-exportedA path the snapshot left out (symlink, submodule, unsafe path).Read it yourself; nothing under it was read.
deadlineTime ran out before the answer was whole.Ask again; narrow the scope if it repeats.
sectionOne section of a composite answer could not be produced.The rest stands; asking again may complete it.
node-capA walk stopped at a node cap.Narrow the scope or ask about fewer symbols.

04 · The worked example

        
How impact works, one hop at a time.

        
It answers three things: what depends on this change, which entrypoints it reaches, and what can this answer not see. The change is always merge-base(base, head)..head.

      


      

        

          
The request

          
ye-ast impact <repo> --base <rev> [--head <rev> | --live] [scope] [budget]

        

        

          
base is the branch the change merges into. head defaults to HEAD. --live replaces head with a working tree declared trusted.

          
budget: --depth, --hub-fan-in, --expansions. None has a default; each one that stops the walk becomes a cut.

Four mechanics that decide the answer

        

          01 Owner at the same depth, then stop ADR-0017
          

            
A route names a class, not a method. When the walk reaches a method, it also reaches the type that declares it, at the same depth and with confidence 1 (walk.ts:62-67). That type then expands only through whole-type edges: extends, implements, and Angular uses-component / uses-directive / uses-pipe. It does not expand into whoever injects or imports it — otherwise a single reached member would drag in the world.

            
src/core/domain/impact/edge-policy.ts:33-39 · src/core/application/impact/inbound-edges.ts:60-70

          

        

        

          02 Interface dispatch, both ways derived by ye-ast
          

            
codegraph's interface-impl bridges stop silently after 40 per class-supertype pair, so ye-ast derives its own: a method and the same-named method of a type above it, for every reached node; downward only when the reached declaration is the changed contract, because a changed declaration changes what its implementations must meet. A path that went up never comes back down to a sibling.

            
src/core/application/impact/inbound-edges.ts:126-137 · src/core/domain/impact/edge-policy.ts:50-55

          

        

        

          03 The this.field.member problem field origin
          

            
this.auth.login() is an unresolved reference, not a call edge. If the class declares auth with a fixed origin, ye-ast settles the use: a field holding the member's type makes the code a caller; a field holding an unrelated type settles it as no use; a field holding a subtype leaves it unsettled. That is why the walk can follow real dispatch without turning every same-named method into a caller.

            
src/core/application/impact/inbound-edges.ts:211-241 · src/core/domain/impact/edge-policy.ts:40-45

          

        

        

          04 Confidence is a widest path, not a count max-min
          

            
A path is as sure as its least sure edge. The walk computes the strongest weakest edge from any seed over all paths; a heuristic edge without a score counts 0.3. In the real run: 1 at the seed, 0.9 at login, 0.85 at onSubmit. Fan-in is separate: it counts call-like callers, whether or not the walk followed them, so a renderer can rank or collapse hubs without the fact cutting them.

            
src/core/application/impact/walk.ts:139-153 · src/core/domain/impact/edge-policy.ts:77-101

05 · The other queries

        
Four questions, one contract.

        
The same fact base, the same scope, the same cut vocabulary. What changes is the seed and the shape of the value.

      


      

        

          
M
map
Where does the system enter?

          
Extracts HTTP routes (Spring), UI routes (Angular), message listeners and scheduled jobs. Each item is a Finding; the collection is the fact. A route the extractor cannot read whole is an unknown item at its location, never a missing row.

          

          
src/core/domain/map/entrypoint-map.ts:20-45 · src/mcp/server.ts:255-270

        


        

          
C
callers
What depends on this symbol or range?

          
Seeds from a requested symbol or a line range instead of a change. No merge base, no changed entrypoints. Use it before changing or deleting a declaration; once the declaration is gone, impact can only list the places that still name it.

          

          
src/core/application/impact/impact-queries.ts:171-213 · src/cli/main.ts:293-310

        


        

          
I
importers
Who imports or uses this file?

          
Per requested file: importers (an imports edge), users (any edge but containment) and unresolvedNamers (files naming the file's stem or a declared symbol without resolving). Tests count here; this is reported information, not a walk edge.

          

          
src/core/application/impact/importers.ts:16-37 · src/core/domain/impact/importers-fact.ts

        

      


      

        

          Which one to reach for
          
MomentQueryWhy

          
            
You are orienting in a repository.mapThe entrypoints are the cheapest map of what the system exposes.

            
You are about to change or delete a declaration.callersIt answers by symbol or line range, before the declaration disappears.

            
You are about to move, rename or re-export a file.importersIt separates importers, users and unresolved namers per file.

            
You finished a change and need the whole picture.impactOne call for the change, with the merge base and the entrypoints it reaches.

          
        

      

    


    
    

      

        
06 · Trust & snapshots

        
Two modes, one rule: the repository never raises its own trust.

        
Trust describes the repository content, never the machine. It is declared outside the repository: by a host through the library or the protocol, by a user through ye-ast init or a flag. Without a declaration, the CLI and the MCP server run untrusted.

      


      

        

          
default
untrusted

          
Reads only a snapshot exported from git at a sha, never the repository itself.

          
    
            
  1. 01 Resolve the revision to a full sha.
    2. 
            
  2. 02 ls-tree lists the tree; only in-scope files are selected.
    3. 
            
  3. 03 cat-file --batch streams each blob into a scratch directory.
    4. 
            
  4. 04 Extractors and codegraph read the export, not the checkout.
    5. 
            
  5. 05 The fact records the sha and the content digest.
    6. 
          

          
    
            
  • No repository code runs.
    • 
            
  • No repository manifest, .gitignore, engine config or pre-built index is honoured.
    • 
            
  • No symlinks, no network.
    • 
          

        


        

          
declared
trusted

          
Adds the working tree and the remote refresh, always into ye-ast's own store.

          
    
            
  1. 01 The same export path at a sha.
    2. 
            
  2. 02 --live replaces head/revision with the working tree.
    3. 
            
  3. 03 git lists paths with ls-files -z --cached --others --exclude-standard.
    4. 
            
  4. 04 ye-ast copies and hashes them into its mirror; codegraph reads the mirror.
    5. 
            
  5. 05 A lock, a state file and sync({ paths }) keep the graph of those bytes.
    6. 
          

          
    
            
  • --live is refused under untrusted with live-requires-trusted.
    • 
            
  • Edits are copied, never hard-linked.
    • 
            
  • A stale answer says so on stderr; the fact itself is unchanged.
    • 
          

        

      


      

        
The live rule: a live fact describes bytes ye-ast copied and hashed, and the graph it reads is the graph of those same bytes. The engine never walks the repository.

        
docs/architecture/rfc/0010-impact-queries.md “Live head” · src/core/application/snapshot/read-snapshot.ts:32-40

      


      

        
Invariants
What never moves

        
    
          
  • Read-only toward agents. The MCP server receives only read query families, so a write is impossible by type (src/mcp/server.ts:21-31).
    • 
          
  • Determinism. Sorted output, repo-relative paths, no index-internal ids, the snapshot in every fact.
    • 
          
  • Redaction before output. Patterns always; by-value secrets only in the process that already holds them.
    • 
          
  • Fail loud, degrade explicitly. A typed failure or an explicit unknown/partial, never an empty result.
    • 
          
  • codegraph only through its adapter. Raw SQL lives there alone, version-checked; telemetry is always off and its CLI shim is never called.

08 · Sources & limits

        
What this page is, and what it is not.

        
This is documentation, not a runtime. It reads the code and the decision records; when they change, the page must change with them.

      


      

        

          
The originating question

          
Can visual-explainer be used for this?

        

        

          
Partly, but not as a library. It is an agent skill: a SKILL.md contract, a kit/ stylesheet and scripts, command templates, and a renderer that writes self-contained HTML into ~/.agent/diagrams/. There is nothing to import at runtime and no component API. Its MCP server prepares and renders pages; it does not ship a UI framework.

          
What this page borrows: the principles the skill is built on — figure first, one visual register, hover-linked emphasis between prose and diagram, a step-through replay, and a self-contained output with no build. What it does not borrow: the kit, the renderer and the MCP server. ye-ast has no build step, and this page must open from the repository with no dependency.

          
visual-explainer is MIT-licensed. If you want its exact palettes, the next step is to vendor kit.css with attribution, or generate a slide deck / MP4 with the skill itself. This page stays dependency-free on purpose.
