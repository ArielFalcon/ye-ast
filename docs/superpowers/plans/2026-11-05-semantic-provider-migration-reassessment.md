# Semantic Provider Migration Reassessment Plan

> **For future evaluators:** This is a research and decision handoff, not authorization to implement, install dependencies, run experiments, remove codegraph, or change production architecture. Use the repository's applicable planning and evaluation workflows if the work is later authorized.

**Goal:** Decide whether important gaps remain after the current engine improvements and whether a partial provider integration, full replacement, or no migration deserves a proposal.

**Architecture:** Preserve the existing fact and query contracts while comparing providers through the same public seams. Each fact has one owner; semantic inputs do not independently write a second dependency graph. No provider or architecture has been accepted here.

**Tech stack:** Node 24.22.2; TypeScript compiler API 6.0.3; experimental Angular Language Service and JDT LS 1.63.0. JDT ran on JVM 25 with effective Java source/compliance/target 17, not a Java 17 API-surface test.

**Spec / evidence basis:** [Current-engine improvements](2026-11-05-current-engine-mechanism-improvements.md) precede this reassessment. The [facts contract](../../architecture/rfc/0002-facts-contract.md), [MCP evaluation skill](../../../.claude/skills/ye-ast-mcp-evaluation/SKILL.md), the ADRs below, and the retained reports are the basis; no new specification or production decision is implied.

## Recommendation and constraints

Improve shared mechanisms in the current engine first. Reassess only remaining consequential, source-demonstrated gaps against that improved baseline. Existing `createProgram`/`getTypeChecker` already resolves some generic and awaited receivers and `getResolvedSignature` selects the correct overload in a direct probe; this is not an MCP improvement and does not require LanguageService. The narrow `Program` → LanguageService `getProgram` swap failed to improve its matched public facts; it did not test the full LanguageService API. No migration, dependency addition, codegraph removal, or architecture change is accepted.

[ADR-0004](../../architecture/adr/0004-codegraph-dependency-with-own-fact-layer.md), [ADR-0008](../../architecture/adr/0008-typescript-compiler-api-source.md), [ADR-0013](../../architecture/adr/0013-coverage-grows-only-with-evidence.md), [ADR-0014](../../architecture/adr/0014-angular-and-spring-from-own-extractors.md), [ADR-0017](../../architecture/adr/0017-owner-of-a-member-expands-only-whole-type-edges.md), and [ADR-0018](../../architecture/adr/0018-type-information-as-a-fact-input.md) remain binding unless superseded through the project's decision process. Codegraph is an indexing technology; dependency relations and traversal are a model that any replacement still needs. Coverage that is unavailable or incomplete must not become a complete empty fact. Preserve snapshots, evidence, determinism, confined reads, read-only agent access and untrusted operation without repository scripts, processors or network.

## Capabilities and limits

The sibling implementation plan now contains a [coverage and residual-opportunity inventory](2026-11-05-current-engine-mechanism-improvements.md#coverage-of-reported-findings), including a gated LS-free Angular/Java feasibility pass. Complete that disposition before claiming that all existing-engine alternatives have been evaluated. This document and the initial plan are not exhaustive audits of every experimental diff.

| Provider / actual API exercised | Public consumer and incremental evidence | Missing coverage / qualification |
|---|---|---|
| TS checker: `createProgram`, `getTypeChecker`, `getResolvedSignature` | Direct generic, await and overload probe; no public MCP gain measured. | Context ownership and joining remain unproved for this probe. |
| TS LanguageService: definitions, `findReferences`, incoming call hierarchy | Overlay supplies selected callers and impact reach; shared B2 fixes prevent attribution of all differences to LS. | Automatic effective project ownership, coverage and independent transitive paths remain open. |
| Angular LS overlay: definitions and references | Exact template method occurrence joins existing traversal in a controlled public query. | Properties/aliases lack precise old-graph seeds in this overlay; the native experiment subsequently selects actual members. Project association, framework compatibility and lifecycle cost remain. |
| JDT LS overlay: references, definitions and incoming hierarchy | Selected generic and overload callers reach public output. | Existing false edge remains in the overlay; native document-symbol inventory and exact binding subsequently distinguish the controlled overloads. Configured classpaths, broader Java and dispatch remain open. |
| Combined semantic providers | Actual stdio MCP with all three, normalized declarations and adjacency. | 24 questions (20 controlled, 4 real), 288 calls and 144 matched pairs; real losses, changed route identity and partial audit preclude replacement. The poisoned codegraph factory and absence audit cover exercised paths only. |

Do not count duplicated edges as gains, compare different primary seeds as equivalent, infer accuracy from fewer cuts, or count direct API answers as public benefits. Require source-level independent positive and negative witnesses for changed associations, including transitive paths. Do not infer global precision, recall or cut reduction from these bounded samples.

## Ordered future gates

The [current-engine correction report](../../../../ye-ast_test/evaluations/runs/20261105T120000Z-current-engine-mechanism-improvements/continuation-v2/report.md) and [residual-family ledger](../../../../ye-ast_test/evaluations/runs/20261105T120000Z-current-engine-mechanism-improvements/continuation-v2/feasibility-ledger.md) now supplement the historical experiments. Bounded occurrence, signature, signal and provenance corrections have been integrated into the working tree without semantic services. Future comparisons must freeze that resulting source state rather than reuse the old baseline as the improved engine. Project ownership remains an architecture gate; initializer widening has a negative safety outcome. Public overload edges, missing reads, Angular member representation/conditional imports and Java semantic targets remain residual questions, with the ledger's separate evidence limits.

- [ ] **Effective context:** Independently verify actual project ownership, overlapping TS configurations, Angular component/template association and Java source roots, effective settings and classpaths. - [ ] **Independent source-path audit:** Freeze positive and negative occurrence-level oracles before queries; reconcile each changed declaration, relation, seed, entrypoint, origin, via, confidence and cut to source, including transitive paths. - [ ] **Representative scopes:** Freeze workloads containing actual real-case families as well as controlled fixtures, including ambiguous same-line selectors, overloads, aliases, generic/await, templates, cross-project boundaries and missing context. Never mix cold and warm measurements or compare different workloads as a speedup; three samples are descriptive, not significance or a threshold.
- [ ] **Public comparison:** Run frozen matched public queries and appropriate project checks under explicitly authorized conditions. Compare full structured facts and independent source paths; record all gains, losses, cuts, input drift, process costs and residual unknowns. Re-run `npm run check` and the broad rule search if implementation changes are subsequently authorized.
- [ ] **Decision gate:** Only after these gates, present a proposed decision for no migration, a selectable partial integration, or full replacement; seek the project owner's architectural decision before production work. Do not create an additional spec or ADR as part of this documentation task. If a later decision contradicts an accepted ADR, use the repository's supersession process.

## Decision criteria

A partial TS, Angular or JDT integration must demonstrate a consequential incremental public-query benefit over the improved engine with source-backed controls and no unexplained loss, retain one fact owner, honor ports and host configuration, and report unavailable coverage honestly. Evaluate each independently; no arbitrary numeric acceptance threshold substitutes for the evidence.

Full replacement additionally requires parity across every advertised tool, language, entrypoint and contract, precise occurrence identity, complete source-path reconciliation for changed outcomes, and actual zero-codegraph proof across all advertised paths and packaged/runtime dependencies. The historical poisoned-factory test proves only its exercised paths. Neither route-contract uncertainty nor partial coverage qualifies as parity. Resource and operational costs must be measured under comparable lifetimes and reviewed alongside correctness.
